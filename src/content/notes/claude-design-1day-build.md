**Claude DesignとClaude CodeとVercelを組み合わせると、プログラミング経験がほぼゼロでも、個人HPを1日で公開できます。** 実際に私が4月25日から26日にかけて体験した手順を、つまずいた7箇所と解決策つきで共有します。

私は八王子・片倉台で月次のスマホ・わいわいサロンを運営している、シニア向けAIリテラシー教育者です。yk_memo というブランドで活動しています。今回、Anthropic社が公開したばかりの「Claude Design」を使い、自分自身のサイトを構築・公開しました。

この記事を読み終えると、次の3つがわかります。

- Claude Design・Claude Code・Vercelの3ツールが、それぞれ何を担うのか
- 1日のスケジュールで、どのフェーズに何時間かかるのか
- 非エンジニアが実際に転ぶポイントと、その乗り越え方

> 【現場レポ】2026年4月25日〜26日にかけての、Claude Design 公開直後の処女作体験です。鮮度のあるうちに、つまずいた箇所も含めてそのまま記録しています。

対象読者は、**40〜60代の自営業・小規模事業主・教育関係者**です。WordPressやJimdoは触ったことがあるが、HTMLは書けない。そんな立ち位置の方を想定しています。

## なぜシニア教育者の私がClaude DesignでHPを作ろうと思ったのか?

**きっかけは「AIと競争しない、自分のベストで使う」という個人的な哲学です。AIに教える立場の自分が、AIを最大限使えていなければ説得力がない。その気づきから、Claude Design 公開のニュースを見た瞬間、自分のサイトで試そうと決めました。**

### 月次サロンの現場で見えていること

私は毎月、地元のシニア向けにスマホ・わいわいサロンを開いています。受講者の多くは70代以上で、AIに対する印象は「便利そう」と「怖い」の間で揺れています。

ある受講者の方が、こう言いました。「私たちの世代は、AIに置き換えられて終わりですね」。この言葉は何度も聞いてきました。

私の答えはいつも同じです。「AIと競争しないでください。自分のベストで使ってください」。

このメッセージを伝え続けるには、自分自身がAIを最大限活用している姿を見せる必要があります。教える人間が使えていなければ、説得力はゼロです。

特に①が決定的でした。一般的なWeb制作では、デザイナーが作ったデザインをエンジニアがコード化する際に、「この余白は何pxですか?」「このフォントは何を使っていますか?」という確認が無数に発生します。これを「ハンドオフ」と呼びます。

> 【哲学】月次サロンで「AIに置き換えられる」と不安を口にする受講者を、私はこれまで数十人見てきました。技術がない人ほど、AIとの協働で得られるレバレッジは大きい。今回のサイト制作は、そのことを自分の身体で確かめる実践でした。

Claude Design と Claude Code の組み合わせでは、このハンドオフが消えます。デザインを作ったAIと、それをコードにするAIが、同じ会話の延長線上にいるからです。

### 既存ツールとの違いは「対話で進む」ことです

WordPressやJimdoを触ったことがある方なら、こう思うかもしれません。「テンプレート選んで色を変えればいいだけでしょう?」と。

それも一つの作り方です。ただ、Claude Design の体験はもう一段違います。「テキストでイメージを伝えると、画面案がいきなり出てくる」のです。テンプレートを選ぶのではなく、自分の言葉でデザインを引き出す感覚に近い。

この違いは、実際にやってみないと伝わりにくいです。次のセクションで、3ツールの役割分担を具体的に整理します。

## Claude Design・Claude Code・Vercelの役割分担とは?

**Claude Designがデザインを生成し、Claude Codeがそのデザインをコード化、Vercelが公開を担います。3つが同じ文脈で繋がるため、デザイナーとエンジニアの間に発生する「ハンドオフ」(仕様伝達の手戻り)が消えます。これが従来のWeb制作との最大の違いです。**

### 従来のWeb制作と何が違うのか?

まず、3ツールの位置づけを整理する前に、従来のWeb制作の流れを確認します。

特に重要なのは「ハンドオフが消える」点です。従来は、「この余白は何pxですか?」「このフォントサイズは正確に何pxですか?」「このアニメーションの細かい挙動は?」といった確認が無数に発生します。デザインとコードの間で意図のズレが起きやすく、ここで時間が溶けます。

Claude Design と Claude Code は、同じ会話の延長線上で動きます。デザインを作った文脈をそのまま実装に持ち込めるため、解釈の違いが生まれる余地がありません。

### Claude Design は何ができるツールか?

**Claude Design は、テキストでイメージを伝えると、Webサイトのデザイン案をブラウザ上で生成してくれるツールです。Anthropic社が提供する、Claudeシリーズのデザイン特化版だと考えてください。**

主にできることは次の通りです。

- ファーストビュー（トップ画面）のデザイン案を複数生成
- ページ内のセクション（特徴、料金、お問い合わせ等）の追加
- 配色・フォント・余白の調整
- 複数ページにわたるデザインの一括生成
- 生成したデザインの HTML/CSS としての書き出し

私の場合、4月25日の朝〜午後にかけて、トップページ・About・Notes・Lessons・Salonの5画面分のデザインを、対話だけで完成させました。

> 【現場レポ】Claude Design の画面を初めて開いた瞬間、「これは今までのデザインツールと違う」と感じました。テキストでイメージを伝えると、いきなり完成度の高い画面案が出てくる。Figmaで2日かけて作っていた工程が、対話で進んでいきます。

注意点として、Claude Design は本記事執筆時点（2026年4月）で公開されたばかりのツールです。Pro プラン以上での利用が必要で、無料プランでは使えません。

### Claude Code は Claude Design とどう繋がるのか?

**Claude Code は、ターミナル（黒い画面）で動くAIコーディング支援ツールです。Claude Design で作ったデザインを、実際に動くWebサイトのコードへ変換する役割を担います。**

Claude Design で生成された HTML を、Claude Code が次のような形で実装に落とし込みます。

- HTMLを Astro という静的サイト生成フレームワークに変換
- TypeScript の型エラーをゼロにする
- 画像・フォント・色などのアセットをサイト用に整理
- GitHubリポジトリへのコミットとプッシュ

ここで Astro という単語が出てきました。Astro とは、表示が高速な軽量サイトを作るための仕組みです。WordPressのように動的にページを生成するのではなく、あらかじめ全ページを書き出しておく方式（静的サイト）なので、表示が速く、運用コストも低く済みます。

Claude Code の何がすごいかというと、これらの作業を「日本語の指示」だけで進められる点です。

```
私：「Claude Design で作った HTML を Astro プロジェクトに変換してください」
Claude Code：「了解しました。プロジェクト構造を作成し、各ページを .astro ファイルに変換します」
```

このやり取りだけで、5画面分のサイトが Astro プロジェクトとして組み上がりました。私は一行もコードを書いていません。

### Vercel を選んだ理由は何か?

**Vercel は、GitHub に置いたコードをワンクリックで本番公開できるホスティングサービスです。個人利用なら無料で使え、ドメイン設定も簡単です。**

ホスティングサービスは他にも GitHub Pages、Netlify、Cloudflare Pages などがあります。今回 Vercel を選んだのは次の3つの理由です。

<table>
  <thead>
    <tr><th>理由</th><th>内容</th></tr>
  </thead>
  <tbody>
    <tr><td>① Astroとの相性</td><td>Vercelは Astro の公式推奨ホスティングの1つ</td></tr>
    <tr><td>② デプロイの簡単さ</td><td>GitHubと連携すれば、push するたびに自動公開</td></tr>
    <tr><td>③ 無料枠が十分</td><td>個人サイト規模なら、月額0円で運用可能</td></tr>
  </tbody>
</table>

「デプロイ」とは、書いたコードを本番のサイトとして公開することです。Vercel では、GitHub のリポジトリを連携するだけで、その後はコードを更新するたびに自動で公開してくれます。一度設定すれば、以降は何も意識しなくて済む仕組みです。

3ツールの役割分担が見えたところで、次は実際の1日のスケジュールに入ります。ただ、その前に「GitHub」「Astro」「Vercel」という言葉に馴染みのない方のために、短い補足を挟ませてください。これを読んでおくと、次のセクションの体感が一段くっきりします。

## 補足解説:GitHub・Astro・Vercel をやさしく理解する

**ここまでに「GitHub」「Astro」「Vercel」という単語が何度か登場しました。次のセクションから具体的な作業手順に入る前に、この3つを身近な比喩で整理しておきます。PCの基本操作はできるが、Web技術の用語は初めて、という方を想定した補足です。**

このサイト制作で出てくる言葉のうち、**Claude Design・Claude Code 以外**の3つの裏方ツールは、それぞれ役割が違います。最初は混同しやすいので、出版業界に置き換えて考えてみます。

### 出版に置き換えて考えると分かりやすい

<table>
  <thead>
    <tr><th>Web用語</th><th>役割の比喩</th><th>何をしてくれるか</th></tr>
  </thead>
  <tbody>
    <tr><td><strong>GitHub</strong></td><td>原稿の保管庫付き図書館</td><td>書いた原稿(コード)を保管し、いつ誰がどこを直したかの履歴を全部残す</td></tr>
    <tr><td><strong>Astro</strong></td><td>印刷工場</td><td>同じ原稿データから、すばやく届けられる完成品(静的サイト)を大量に印刷する</td></tr>
    <tr><td><strong>Vercel</strong></td><td>出版・配送センター</td><td>印刷した本を、世界中の読者にすばやく届ける流通網を持っている</td></tr>
  </tbody>
</table>

3つの関係を一文で言えば、**「GitHubに保管された原稿を、Astroが本に仕上げ、Vercelが世界中に配る」**となります。私たちは、この流れを一度設定するだけで、あとは「原稿を更新する」だけでサイトが自動で世界中に届きます。

### なぜこの3つがセットで使われるのか?

**結論から言うと、それぞれが得意分野を分担しているからです。1社のサービスにすべてを任せる従来の方式(WordPressなど)よりも、軽くて速くて安くなります。**

それぞれの得意分野を整理します。

- **GitHub**:変更履歴の管理が得意。「3日前のバージョンに戻したい」も簡単
- **Astro**:表示速度が得意。読者を待たせない軽いサイトが作れる
- **Vercel**:公開作業が得意。GitHubに変更を上げると、自動で本番に反映してくれる

特に最後の「自動で本番に反映」が、従来のWeb制作と一番違う点です。昔のWeb制作では、ファイルをサーバーに手動でアップロードする必要がありました。Vercelを使うと、その作業が消えます。**「原稿を保存する感覚で、本番が更新される」**という新しい体験が手に入ります。

### この3つは、すべて無料で使える

**個人サイト規模であれば、GitHub・Vercelとも無料プランで十分です。Astroはオープンソースなので、そもそも料金という概念がありません。**

これは初心者にとって大きな安心材料です。「使いこなせなかったら課金が無駄になる」という心配がありません。失敗しても、お金は1円もかかっていない状態です。**3つすべて、登録だけしておいて、使わなくても損をしない**という気軽さがあります。

### 用語に詳しくなる必要はない

ここまで読んで「やっぱり難しい」と感じても大丈夫です。**この3つの中身を完全に理解する必要はありません**。Claude Codeに「GitHubにpushして」「Vercelにデプロイして」と日本語で頼めば、適切な操作を進めてくれます。

ただ、頭の片隅に「GitHub=保管庫」「Astro=印刷工場」「Vercel=配送センター」というイメージがあると、エラーが出たときに「これはどの段階で起きているのか?」が見えやすくなります。次のセクションで紹介する1日のスケジュールも、この3つの役割を行き来する旅だと思って読んでください。

ここからの手順は、本章で説明した3つのツールが、実際にどう動くかの実例です。

### フェーズ1:デザイン構想と参考リサーチ(4/25 朝・3時間)

**最初の3時間は、Claude Design に触る前の「準備」に使いました。何を作りたいかが曖昧なまま生成AIに頼ると、出てくるアウトプットも曖昧になります。**

朝の作業内容は次の通りです。

- 参考にしたい個人サイトを5〜7サイト集めてブックマーク
- それぞれの「何が好きか」を Obsidian に箇条書きで書き出す(余白の取り方、配色、フォント、情報密度)
- yk_memo として伝えたい3つのメッセージを言語化
- 必要なページ構成(IA: 情報設計)を決定

特に時間をかけたのは、「Obsidian に好みを言語化する作業」です。「シンプル・余白多め」と書くだけでは弱い。「Linear や Vercel のようなミニマルだが温度のある余白」「黒に近いグレーのテキスト」「セリフ体は使わずサンセリフで統一」と、具体性を上げていきます。

> 【現場レポ】この準備フェーズは、AIを使う上で一番大事な工程だと改めて感じました。Claude Design は優秀ですが、「適当に頼むと、適当なものが返ってくる」のは他のAIと同じです。準備に3時間かけたおかげで、午後の生成作業が圧倒的に速く進みました。

### フェーズ2:Claude Design で5画面を生成(4/25 午後・4時間)

**午後はいよいよ Claude Design の本番です。朝の準備で言語化した好みと5ページ構成をプロンプトに落とし込み、4時間で全画面の方向性を固めました。**

進め方は次の流れです。

1. **トップページのファーストビューを最初に作る** - 一番こだわるべき画面
2. **方向性が固まったら、他4ページに同じ世界観を展開する**
3. **配色・タイポグラフィ・余白を全画面で統一する**
4. **細部の調整(間延びしている箇所、密度が足りない箇所)を反復**

この順番が大事でした。最初にトップを完成させずに5画面を並行で作ろうとすると、世界観がバラけます。トップが「この方向で行こう」と決まれば、残りは「同じ世界観で」と一言伝えるだけで揃います。

> 【現場レポ】Figmaで2日かけてやっていた作業が、対話で進んでいく感覚は新鮮でした。「もう少し余白を広く」「ヘッダーをスティッキーにして」「カードの角を少し丸く」と日本語で伝えると、その場で反映される。デザインツールというより、デザイナーと会話している感覚に近いです。

## 実際にどこでつまずいたのか?(7箇所のリアル)

**私が転んだのは7箇所。TypeScript型エラー、HTML→Astro変換の構文、画像パス、Git操作、Vercelビルド失敗、ブラウザキャッシュ、スマホ表示の崩れです。すべて、Claude Code(コード修正)と Claude チャット(疑問相談)を使い分けることで、15分以内に解決できました。一人だったら、ここで挫折していた自信があります。**

各つまずきは「**何が起きたか → なぜ起きたか → どう解決したか → 教訓**」の4点セットで書きます。読者が同じ場面に遭遇したときの参照辞典として使ってください。

なお、私はターミナル(黒い画面)操作が苦手なので、**Google Antigravity** をターミナルの代わりに使い、その中で Claude Code を動かしました。Git の操作も、コマンドラインを叩くのではなく **GitHub Desktop** という画面付きのツールで完結させています。**つまり、今回のサイト制作で、私は黒いターミナル画面を一度も開いていません**。この事実が、後述する各つまずきの解決にも効いてきます。

### つまずき①:TypeScript 型エラーで Vercel デプロイが落ちた

**何が起きたか**:GitHub Desktop で push 後、Vercel のダッシュボードでビルドが赤く失敗。「Type error: Property '〜' does not exist on type '〜'」というメッセージが大量に並びました。

**なぜ起きたか**:Claude Design が生成した HTML を Astro に変換する際、Astro の型定義(プロパティに「これは文字列」「これは数値」と宣言する仕組み)に合わない箇所がいくつか残っていたためです。Astro はこの型チェックが厳格で、1箇所でも合わないとビルド全体が止まります。

**どう解決したか**:Claude Codeに次のように依頼しました。

```
このAstroプロジェクトの全ファイルを型チェックして、
TypeScriptエラーがゼロになるように修正してください。
変更内容は1つずつ説明してください。
```

Claude Code は5分ほどで全ファイルをスキャンし、修正案を提示。私は「OK、進めてください」と返すだけで、すべての型エラーが解消されました。

> 【失敗談】最初は「型エラー」という言葉自体がよく分からず、Vercelのエラー画面を10分くらい眺めていました。「型」って何?と。後から振り返ると、これは「変数に入るデータの種類(文字列・数値・真偽値など)」のチェックなのですが、初見では意味不明です。理解できなくても、Claude Codeに丸投げすれば動くようにしてくれます。

**教訓**:エラーメッセージの意味を完全に理解する必要はありません。エラー文を全文コピーして「これを直してください」とAIに渡せば、ほとんどのケースで解決します。

### つまずき②:Claude Design の HTML を Astro に変換するときの構文の壁

**何が起きたか**:Claude Design からエクスポートした HTML をそのまま Astro プロジェクトに置いても、動きませんでした。「Unexpected token」というエラーが出て、ローカルサーバーが起動しません。

**なぜ起きたか**:Astro は「.html」ではなく「.astro」という独自の拡張子を使います。両者はよく似ていますが、ファイル先頭に「---」で区切られたフロントマター(設定情報を書く領域)が必要だったり、JavaScriptの埋め込み方が違ったりします。生のHTMLをそのまま `.astro` ファイルにリネームしただけでは動きません。

**どう解決したか**:Claude Code に次のように指示しました。

```
このHTMLファイルをAstroの.astroコンポーネントに変換してください。
共通で使える部分(ヘッダー・フッター・レイアウト)は別ファイルに切り出して、
全ページから読み込めるようにしてください。
```

ここでも Claude Code は構造を理解した上で、5画面分のHTMLをそれぞれ `.astro` に変換し、共通部分を `Layout.astro` という1ファイルに抜き出してくれました。

> 【現場レポ】このとき初めて、「コンポーネント化」という考え方を体験で理解しました。ヘッダーを5画面それぞれに書くのではなく、1つのファイルに書いて全画面から呼び出す。後で1箇所変えれば全画面に反映される。**この設計思想を、コードを書かずに体験で学べた**のは大きな収穫でした。

**教訓**:Claude Design と Claude Code は名前は似ていますが、扱う「言語」が少し違います。間に変換作業が必要だと知っておくと、心の準備ができます。

### つまずき③:画像のパスがローカルと本番で違った

**何が起きたか**:ローカル(自分のMac)では画像が正常に表示されるのに、Vercel に公開した本番サイトでは画像が表示されず、四角い枠と「×」マークだけが残っていました。

**なぜ起きたか**:Astroでは、画像ファイルを置く場所と、それを呼び出すパス(住所)に決まりがあります。私は最初、Claude Design からダウンロードした画像をプロジェクトの好きな場所に置いていました。ローカルでは偶然動きましたが、本番ビルド時にはAstro が「正しい場所に置かれた画像」しか認識しません。

**どう解決したか**:Claude Code に次のように頼みました。

```
このプロジェクトの画像ファイルを、
Astroが認識する正しい場所(public/ もしくは src/assets/)に整理してください。
全ページの<img>タグも、新しいパスに合わせて修正してください。
```

これで、画像が `public/images/` フォルダに整理され、各ページの読み込みパスもすべて `/images/xxx.png` の形式に統一されました。本番サイトでも画像が正常に表示されるようになりました。

> 【失敗談】最初に Vercel の本番サイトを開いて、トップに大きな「×」が並んだときは、心臓が止まりそうでした。「公開した瞬間に壊れた」と思って。しかし、Claude Code に画面のスクリーンショットを撮って渡すと、原因をすぐに特定してくれました。

**教訓**:「ローカルで動く」と「本番で動く」は別物です。違いの大半は、ファイルの置き場所のルールに起因します。Claude Code はこのルールを理解しているので、初心者は頼り切ってよい領域です。

### つまずき④:Git push でリポジトリの初期設定に迷った

**何が起きたか**:GitHub Desktop でリポジトリを作成し、いざ「Publish repository」のボタンを押したとき、「リポジトリ名」「Public/Private の選択」「README を含めるか」などを聞かれて、どれを選ぶのが正解か分かりませんでした。

**なぜ起きたか**:Git や GitHub の概念(リポジトリ・コミット・ブランチ・リモート)に馴染みがないと、最初の一歩で必ず迷います。「とりあえず Private で」と選んでも、後で Vercel と連携するときに「Public じゃないと無料プランで使えない場合があるのでは?」と不安になります。

**どう解決したか**:Claude チャットに次のように相談しました。

```
GitHubに個人サイトのコードを上げます。
Vercelで無料公開する前提で、
リポジトリ名・Public/Private・READMEの有無について、推奨設定を教えてください。
```

回答は明快でした。

- **リポジトリ名**:サイト名と同じが分かりやすい(私は `yk-memo` にしました)
- **Public/Private**:Privateで問題ない。Vercelは Private リポジトリでも無料連携できる
- **README**:後から追加でよい。最初は空でもOK

この回答で迷いが消え、3分で GitHub Desktop の設定を完了できました。

> 【現場レポ】GitHub Desktop は本当にありがたい存在でした。ターミナルで `git init`、`git add .`、`git commit -m "..."`、`git push origin main` を打つ必要がありません。すべてGUIのボタンで完結します。シニア教育の現場で「ターミナルが怖い」という声をよく聞きますが、**Git周りはGitHub Desktopで完全に回避できます**。

**教訓**:迷う場所では、Claude チャットに「初心者向けの推奨設定」を聞くのが最速です。プロの設定ではなく、初心者が選ぶべき設定を聞く、という質問の仕方が大事です。

### つまずき⑤:Vercel のビルドが2回連続で落ちた

**何が起きたか**:GitHub と Vercel を連携し、初回のデプロイを実行。すると、Vercel のダッシュボードでビルドが「Failed」と表示。修正してもう一度試したが、また失敗。心が折れかけました。

**なぜ起きたか**:1回目は前述のTypeScript型エラー(つまずき①)、2回目は「package.json の依存関係(必要なライブラリのリスト)に記載漏れがあった」ことが原因でした。ローカルでは動いていたのですが、Vercel は本番環境でクリーンな状態からビルドし直すため、ローカル限定で動いていたものは検知されます。

**どう解決したか**:Claude チャットに Vercel のビルドログ(エラー記録の長文)を全文貼り付け、こう聞きました。

```
このVercelのビルドエラーログを読んで、
原因と修正方法を初心者向けに説明してください。
```

Claude チャットはログから「`xxx というモジュールが見つからない` という記述を発見しました。これは依存関係の宣言漏れです」と原因を特定。提案された `package.json` への追記は、続けて Claude Code でファイルを修正してもらいました。3回目のデプロイでビルドが緑色の「Ready」になり、サイトが本番公開されました。

> 【失敗談】2回連続でビルドが赤く落ちたとき、「やっぱり自分には向いてないのでは」と一瞬思いました。でも、ここで諦めずに3回目を試したことが正解でした。**赤い「Failed」を3回見たら、4回目で必ず緑になる**くらいの気持ちで臨むと、精神衛生的にも楽です。

**教訓**:エラーログは長くて怖く見えますが、Claude チャットに全文渡せば翻訳してくれます。最初の数回は失敗するのが普通です。

### つまずき⑥:ブラウザのキャッシュで変更が反映されない

**何が起きたか**:Vercelで再デプロイしたあと、自分のブラウザでサイトを再読み込みしても、古いままの表示が消えませんでした。「あれ、修正が反映されていない?Vercelの設定が間違っているのか?」と20分ほど悩みました。

**なぜ起きたか**:ブラウザには「キャッシュ」という仕組みがあり、一度読み込んだサイトの内容を一時的に保存しておきます。これにより表示が高速になりますが、サイトを更新した直後は古いキャッシュが優先されてしまうことがあります。

**どう解決したか**:解決策は3つあります。

1. **ハードリロード**:Mac なら `Command + Shift + R`、Windows なら `Ctrl + Shift + F5`
2. **シークレットウィンドウで開く**:キャッシュを使わずにアクセスできる
3. **別のデバイスで確認する**:スマホで開けば、PC のキャッシュとは無関係

私は最初、原因がキャッシュだと気づかず、Vercelのデプロイ設定を何度も見直しました。Claude チャットに「再デプロイしたのに変わらない」と相談したら、最初に「ハードリロードを試しましたか?」と聞かれて、解決しました。

> 【現場レポ】これはシニア教育の現場でも頻発するトラブルです。「LINEで送ったはずなのに表示されない」「アプリを更新したのに変わらない」と相談されたとき、**8割は再起動とキャッシュクリアで解決**します。今回、自分自身もこの罠にはまったことで、月次サロンで教える説得力が増しました。

**教訓**:「変わらない時はキャッシュ」は、シニア向けITトラブル対応の三大原則の1つです(他の2つは「再起動」と「ネット接続確認」)。

### つまずき⑦:スマホ表示でレイアウトが崩れた

**何が起きたか**:PCのブラウザでは綺麗に表示されているサイトが、スマホで開くと文字が画面からはみ出したり、ボタンが小さすぎたり、画像がページ幅を超えていたりしました。

**なぜ起きたか**:Webサイトは画面サイズに応じて見え方を調整する「レスポンシブデザイン」という設計思想で作るのが現代の標準です。Claude Designで生成された画面はPC前提のデザインだったため、スマホサイズに対応するCSS(画面の見た目を制御するコード)が部分的に不足していました。

**どう解決したか**:Claude Code に次のように依頼しました。

```
このサイトをスマホで開いたときに崩れる箇所を全部洗い出して、
レスポンシブ対応のCSSを追加してください。
特に下記を確認してください:
- 文字が画面からはみ出していないか
- ボタンがタップしやすい大きさか
- 画像が画面幅を超えていないか
```

Claude Code は全画面のCSSを点検し、スマホ用のメディアクエリ(画面サイズに応じてスタイルを切り替える仕組み)を追加してくれました。修正後は、iPhoneでもAndroidでも、PC同様に綺麗に表示されました。

> 【失敗談】これが一番ショックだった転びどころです。PCで満足のいく仕上がりだったので、スマホ確認を後回しにしていました。スマホで開いた瞬間、メニューが画面からはみ出して、ボタンが押せない状態。**シニア向けサイトを作る人間として、スマホで崩れているのは致命的**です。私の月次サロンの参加者は、ほぼ全員スマホでサイトを見ます。

**教訓**:**作業の早い段階でスマホ表示を確認する**こと。PCでデザインを進める時間と、スマホで動作確認する時間を、最低でも2:1の割合で取ったほうが安全です。

エンジニアであれば、Claude Codeが書いたコードを1行ずつ読んで理解しようとします。しかし、非エンジニアにはそれができません。私自身、Claude Codeが書いた `.astro` ファイルや `package.json` の中身を、すべては理解していません。

ここで2つの態度がありえます。

- 態度A:「理解できないコードを使うのは怖い。全部わかるまで進めない」
- 態度B:「動いているなら、それでいい。必要に迫られたら理解する」

私は **態度B** を選びました。月次サロンで「AIと競争しない、自分のベストで使う」と教えている人間が、ここで態度Aを取ると矛盾するからです。

> 【哲学】月次サロンの受講者の中には、**「AIに任せて間違いがあったら困る」**と心配される方が多くいます。私の答えはこうです。「間違いを防ぐためにAIを使うのではなく、間違いに気づきやすい仕組みを作るためにAIを使うのです」。Claude Code は確かに完璧ではありません。しかし、エラーが出たときに「これを直してください」と頼めば、また直してくれます。**完璧を求めず、対話を続ける覚悟**が、AI時代のサイト制作の一番の準備です。

## よくある質問(FAQ)

ここまで読んでくださった方が、まだ持っているかもしれない疑問に、まとめてお答えします。

### Q1. Claude Design は無料で使えますか?

**A. 2026年4月時点では、Claude の Pro プラン以上での利用が前提です。無料プランでは Claude Design は使えません。**

Pro プランは月額20ドル前後で、Claude Design・Claude Code を含む高度な機能が使えるようになります。一度サイトを完成させてしまえば、その後の運用に Claude のサブスクは必須ではありません(GitHub と Vercel は無料のまま使い続けられます)。

「サイト制作の期間だけ Pro に入って、完成したら解約する」という使い方も可能です。

### Q2. プログラミング知識ゼロでも、本当にできますか?

**A. はい、できます。ただし「ゼロ」の定義によります。コードが書けないのは問題ありませんが、「ファイル」「フォルダ」「ブラウザ」「URL」というPC操作の基本語彙は必要です。**

WordPress を触ったことがあるレベルがあれば、技術的な土台は十分です。それ未満の場合は、まず Mac の Finder や Windows のエクスプローラーで「フォルダを作る・名前を変える・中身を移動する」という練習を1時間ほどしておくと、サイト制作中の混乱が減ります。

### Q3. Vercel と GitHub Pages では、どちらが良いですか?

**A. 個人サイト用途なら、Vercel をおすすめします。理由は3つあります。Astro との相性が良いこと、デプロイが自動化できること、無料枠が十分であることです。**

GitHub Pages も無料で使えますが、Astro のような静的サイトジェネレータとの連携は Vercel のほうが洗練されています。「git push したら自動で本番に反映される」という体験は、Vercel ならではです。

迷う場合は Vercel から始めて、後でGitHub Pages や Cloudflare Pages に移すこともできます。一度作ったコードは、ホスティング先を変えても流用可能です。

### Q5. 公開後の更新は、どうやって行いますか?

**A. ローカル(自分のMac)でファイルを修正し、GitHub Desktop で push するだけです。Vercel が自動で本番に反映してくれるため、「サイト更新作業」という大げさな概念がありません。**

具体的には次の流れです。

1. Antigravity と Claude Code でファイルを修正(または手動で `.md` ファイルを編集)
2. GitHub Desktop で「Commit」してから「Push」
3. 1〜2分後、Vercel が自動で本番に反映

慣れてくると、文章を保存する感覚で本番が更新される体験になります。記事を1本追加するなら、5分〜10分で済みます。

### Q7. つまずいたら、誰に相談すればいいですか?

**A. 第一の相談相手は、Claude そのものです。「これは何ですか?」「どうすればいいですか?」と意味や方針を聞きたいときは Claude チャット、「ファイルを直してください」「コードを書いてください」と作業を頼みたいときは Claude Code。エラーメッセージやスクリーンショットを渡せば、ほとんどのケースで解決策が返ってきます。**

それでも解決しない場合は、次の順序で人に相談するのが現実的です。

1. **Claude チャットに、表現を変えて再質問**(別の言い方で聞くと答えが変わる)
2. **GitHub の Issues や Discussions**(同じエラーの解決例が見つかる)
3. **AIに詳しい知人や、地域のITコミュニティ**(顔の見える相談)
4. **Anthropic の公式ドキュメント**(英語だが情報源として確実)

私自身、月次サロンで「困ったら、まずAIに聞き直してみてください」と伝えています。質問の仕方を変えるだけで、答えの質が大きく変わるからです。

### Q8. 同じことを Claude Cowork でもできますか?

**A. はい、Claude Cowork(デスクトップ版)を使えば、ターミナルや Antigravity を使わずに、より直感的な操作でサイト制作ができます。本当に技術操作が苦手な方には、Cowork のほうが向いています。**

Claude Cowork は、ターミナル操作を一切意識せずに、Claude Code 相当の作業を進められる仕組みです。フォルダを指定して「このサイトを作って」と日本語で伝えるだけ。私の今回のワークフローを Cowork で再現すれば、さらに敷居が下がります。

ただし、私自身は今回 Antigravity + Claude Code で進めました。理由は、**プロセスの細部まで自分で見たかった**ことです。教育者として、「中で何が起きているか」を理解しておきたかった。同じ理由で、これから挑戦される方も「Cowork から始める / Antigravity から始める」のどちらでも構いません。
