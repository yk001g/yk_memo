この記事は、私自身が2026年5月3日に丸1日かけて、八王子竹紙研究会のブランディング動画（90秒・BGM付き）を**完全にゼロから完成させた実体験の記録**です。

途中で4回詰まりました。BGMが5秒で消える謎、出力したMP4が無音だった事件、そもそもプレビューと出力(render)を勘違いしていた話 — そういう「実際にやった人にしか書けない失敗」も全部書きます。

これから「AIで動画を作ってみたい」と思っている**個人事業主・講師・NPO関係者・クリエイター**の方が、同じ罠にハマらず最短ルートで動画を完成させられるように、この記事を残します。

## なぜいまAIで動画を作るべきなのですか？

**動画制作の外注相場は1本5〜10万円・納期2週間が今も主流です。それを「90秒・1日・ゼロ円」で完成できる時代になりました。最大の壁は技術ではなく「最初の一歩」です。**

個人事業主・講師・NPOにとって、動画は「あったら強い」武器ですが、外注すると重いコストになります。10秒のSNSヘッダー動画でも数万円、5分のセミナー紹介動画なら10万円超えが普通です。修正のたびに追加費用も発生します。

一方で、After EffectsやPremiereを自分で習得するのも厳しい現実があります。学習コストが大きく、操作を覚えるだけで何ヶ月もかかります。多忙な個人事業主には、その時間がそもそもありません。

ここに**第三の選択肢**として登場したのが、HeyGen社が2026年4月にOSSで公開した**Hyperframes**です。Claude Code（AnthropicのAIコーディングエージェント）と組み合わせれば、自然言語で指示するだけで動画が作れます。

> 【実体験】数年前、私自身もNPOの紹介動画で外注見積もりを取ったことがあります。「90秒で◯万円、修正は1回まで」という条件を見て、その場で諦めました。今日この記事を書きながら、当時の自分に「待っててよかった」と言いたい気持ちです。

ただし重要な前提があります。AIで動画ができるとはいえ、**完全に放置で完成するわけではありません**。設計の勘所、AIへの指示の出し方、つまずいた時の解決手順は、人間が知っておく必要があります。

この記事はまさに、その「**人間が知っておくべき部分**」を体験ベースでお伝えするものです。

## Hyperframesとは何ですか？Claude Codeとの違いは？

**HyperframesはHeyGen社がOSSで公開したHTML→動画フレームワークです。Claude Codeと組むと「自然言語で指示→HTML自動生成→MP4出力」という流れが成立します。両者は競合ではなく補完関係にあります。**

Hyperframesは、HTMLとCSS・JavaScriptで動画を「書く」ための仕組みです。タイムラインや特殊効果をHTML上のdata属性で指定すると、ヘッドレスChromeが90秒分のフレームを描画し、FFmpegがMP4に変換します。

一方のClaude Codeは、Anthropic社のターミナル型AIエージェントです。「動画を90秒で作って」と話しかけると、HyperframesのHTMLを書いてくれます。

つまり関係性はこうなります。

- **Hyperframes** = 動画を書くための言語（HTML+α）
- **Claude Code** = HTMLを書いてくれるAI翻訳者
- **YK（あなた）** = 動画の方向性を伝える指示出し役

人間がやることは「**何の動画を作りたいか**」を伝えるだけ。実際のコードはAIが書きます。

### HyperframesがRemotionと違う点は？

**HyperframesはReact不要・素のHTML・無料無制限商用OK。LLMが学習データを大量に持つWeb技術そのままで書けるため、AI生成との相性が圧倒的に良いです。**

似たツールにRemotionというReactベースの動画フレームワークがあります。比較するとこうなります。

| 項目 | Hyperframes | Remotion |
|---|---|---|
| ベース技術 | 素のHTML+CSS+JS | React必須 |
| ライセンス | Apache 2.0（無料・商用可） | 一部有料ライセンスあり |
| AIとの相性 | ◎（HTMLは学習データ豊富） | △（React独自パターンの学習が必要） |
| 学習コスト | 低（HTMLの基本知識で書ける） | 高（Reactの理解が前提） |
| エージェント設計 | 最初からエージェント前提 | 人間の開発者前提 |

特に重要なのが**ライセンスとAIとの相性**です。Hyperframesは完全に無料で商用利用OKで、しかもLLMが大量に学習しているHTML/CSSベースなので、Claude Codeに「フェードインのアニメーションを足して」と頼むと一発で書けます。

> 【現場の判断】私はRemotionも触ったことがありますが、Reactのコンポーネント設計を考える時間が長く、AIに任せても結局自分でデバッグする場面が多かった経験があります。Hyperframesは「HTMLそのまま」なので、AIが書いたコードを人間が読んで理解できる安心感が違います。

## 動画制作に必要な準備は何ですか？（環境構築）

**Mac前提でHomebrew・Node.js（v22以上）・FFmpeg・Claude Codeの4点が必要です。所要時間は15〜30分。「ターミナルが怖い」初心者がまず最初に躓くポイントを先回りで解説します。**

最初に正直にお伝えしておきます。**この最初の30分が、ある意味で記事全体で一番のハードル**です。なぜなら、ターミナル（黒い画面でコマンドを打つアプリ）に慣れていない人にとって、最初の一歩が心理的に重いからです。

ですが大丈夫です。やることはたったの4ステップで、各ステップは「指定されたコマンドをコピペしてEnter」だけです。

### 環境構築の4ステップ

1. **Homebrew**をインストール（Macアプリの管理ツール）
2. **Node.js v22以上**をインストール
3. **FFmpeg**をインストール（動画・音声処理エンジン）
4. **Claude Code**をインストール（AIエージェント本体）

各ステップの詳細手順は[Hyperframes公式ドキュメント](https://hyperframes.heygen.com/quickstart.md)に載っています。1つずつ実行して、それぞれのバージョン確認コマンドで動作確認するのがコツです。

> 【失敗談】私は環境構築でも一度ハマっています。プロジェクトを外付けSSD（`/Volumes/Data-yk1/`）に置いたところ、ターミナルから日本語フォルダ名「書類２」（全角2）にアクセスする際、半角2と打ち間違えていて30分溶かしました。**初心者は外付けSSDではなくMac本体の `~/Documents/` 直下に置くのが安全**です。

### バージョン確認コマンド

環境構築が終わったら、ターミナルで以下を順に打って確認してください。

```bash
brew --version       # Homebrew 5.x.x が出ればOK
node --version       # v22以上ならOK
ffmpeg -version      # ffmpeg version 6.x or 7.x or 8.x ならOK
claude --version     # Claude Codeのバージョン番号が出ればOK
```

すべて表示されれば環境構築は完了です。「`command not found`」が出たらインストールが完了していないので、もう一度該当ステップに戻ります。

## 90秒の動画はどう設計すればいいですか？

**PDFや記事を入力に、AIと対話して8シーン・90秒の構成を作るのが王道です。テロップ文言と画像配置を設計図に落とし込めば、あとはAIが書いてくれます。**

設計フェーズは、AIに動画を作らせる前の「**準備運動**」のような重要な時間です。ここを丁寧にやると、生成された動画の修正回数が激減します。

私が実際に取った設計プロセスはこうでした。

1. 八王子竹紙研究会の**13ページのPDF資料**をClaude（私）に読み込ませる
2. PDFの内容から「物語の起承転結」を一緒に整理する
3. **8シーン・90秒**の構成案を作る（オープニング → 課題 → 解決 → 工程説明 → 完成品 → コミュニティ → CTA）
4. 各シーンのテロップ文言を決める
5. 各シーンに必要な画像の枚数と内容を決める

> 【実体験】竹紙研究会のPDFをClaudeに読み込ませた瞬間、すぐに「**竹が、息を吹き返すとき**」という詩的なメインコピーが提案されました。これは元のPDFの表紙にあった言葉でした。AIは私が見落としていた「資料の中で最も強い言葉」を瞬時に拾い上げてくれたのです。これは外注先のデザイナーに伝言ゲームしていたら絶対に出てこなかった成果です。

設計フェーズの所要時間は**30〜60分**程度。この時間がそのまま動画のクオリティに直結します。

## 素材は自分の写真でも大丈夫ですか？ Pexelsとどちらがいい？

**結論から言えば、自分の活動写真の方が圧倒的にブランド価値が高いです。Pexelsの汎用素材より、自分で撮った写真をKen Burns効果（ゆっくりズーム/パン）で動かす方がドキュメンタリー感が出ます。**

私は最初、無料素材サイトのPexelsから動画素材をダウンロードしようとしていました。「bamboo forest sunlight」のような英語キーワードで検索して、雰囲気の合う動画を10本ほど集める計画でした。

しかし途中で**方針を完全に転換**しました。「**自分で撮った写真を使えばいいじゃないか**」と気づいたからです。

### Pexelsと自分の写真の比較

| 項目 | Pexels（無料動画素材） | 自分で撮った写真 |
|---|---|---|
| オリジナリティ | △（汎用） | ◎（本物の活動写真） |
| ブランド価値 | △ | ◎ |
| 入手の手間 | 30〜45分の検索作業 | 既に手元にある |
| 動きの自然さ | ◎（動画なので） | ○（Ken Burns効果で補完） |
| 視聴者への説得力 | △ | ◎（実在の活動） |

> 【現場の判断】Pexelsの「bamboo forest」素材は美しいのですが、よく見ると東南アジアやヨーロッパで撮影された竹林ばかりです。「八王子の里山」のリアリティとは別物。一方、自分で撮った写真には**伐採作業をしている本人の手**や**実際の体験講習会の笑顔**が映っています。これは外注では絶対に手に入らない素材です。

私が最終的に集めたのは、自分のフォトライブラリから選んだ**21枚の写真**でした。撮影日は数年にわたっており、活動の歴史そのものが収まっています。

ただし注意点があります。横構図（16:9）の写真を優先すること、解像度はできれば2560px以上、被写体が中央寄りにあるもの、です。Ken Burns効果で拡大した時に被写体が切れないように、撮影時より少し広めに余白がある写真がベストです。

## AIに動画HTMLを書かせる手順は？

**プロジェクト初期化→画像配置→Claude Codeに構成プロンプトを投げる→生成されたHTMLをプレビュー→修正指示→レンダリング、の6ステップです。**

ここからが「AIに実際に作らせる」フェーズです。ステップごとに見ていきましょう。

### Step 1: プロジェクトの初期化

ターミナルで以下を実行します。

```bash
npx hyperframes init bamboo-paper-story --example warm-grain
cd bamboo-paper-story
mkdir -p assets/images
```

これで `bamboo-paper-story` というフォルダが作られ、その中に動画プロジェクトの雛形が配置されます。

### Step 2: 画像を配置

集めた21枚の写真を `assets/images/` に置きます。ファイル名は `01a-opening-bamboo.jpg` のように **シーン番号＋連番＋意味のある名前** にしておくと、後でAIに指示する時に楽です。

### Step 3: Claude Codeに構成プロンプトを投げる

ここがメインイベントです。Claude Codeを起動して、以下のような長めのプロンプトを投げます（実際は1,500字くらいの詳細プロンプトを書きました）。

```markdown
/hyperframes

90秒のブランディング動画を作成してください。
テーマは「八王子竹紙研究会」の活動紹介で、
自分で撮影した実写写真にKen Burns効果を加えて動画的に表現します。

[シーン構成、配置する画像のファイル名、テロップ文言、
カラーパレット、フォント指定などを詳細に書く]
```

このプロンプトをペーストすると、Claude Codeが**約2〜5分**で `index.html` を800行ほど書き上げます。

### Step 4〜6: プレビュー・修正・レンダリング

生成されたHTMLは、以下のコマンドで確認・出力できます。

```bash
npm run dev      # ブラウザでプレビュー
npm run check    # エラーチェック
npm run render   # MP4ファイルとして出力
```

> 【独自検証】私は最初Antigravity（Google Geminiベースのコーディング環境）でHTML初期生成をしましたが、途中で動作が不安定になりました。Claude Codeに切り替えたところ安定して動き、特に**修正フェーズの細かい属性調整がClaude Codeの方が圧倒的に強かった**です。**初期生成はAntigravity、修正はClaude Code**という使い分けが現実的だと感じました。

## 動画制作で実際に詰まった3つの場所はどこですか？

**1日の制作で時間を溶かしたのは「①プレビューと出力(render)を勘違い」「②BGMが5秒で停止」「③MP4で完全無音」の3つ。すべてHyperframes公式仕様の理解不足が原因でした。**

ここが**この記事の核**です。AIで動画が作れる時代でも、人間が「どこで詰まるか」を知っておくことが結局一番の時短になります。

### 失敗①：プレビューと出力(render)の混同

**症状**：「`npm run render` を実行して動画ができた」と思っていたら、生成されたMP4ファイルがどこにも存在しなかった。

**原因**：私が実行していたのは `npm run dev`（プレビュー）だけで、ブラウザで完成した動画が見えていたので「もう完成した」と勘違いしていました。プレビューはあくまで**ブラウザで再生して見るための機能**で、MP4ファイルは出力されません。

**解決**：明確に2つは別物だと理解する。

| コマンド | 用途 | 結果 |
|---|---|---|
| `npm run dev` | プレビュー（編集確認） | ブラウザで再生可能 |
| `npm run render` | MP4出力（最終版） | `renders/`フォルダにMP4ファイル作成 |

> 【失敗談】この勘違いで2時間ほど「ファイルが見つからない」と探し回りました。最終的に、ターミナル履歴を遡って実行コマンドを確認することで判明しました。**「ブラウザで見える＝完成」ではない**ことを覚えておけば、同じ失敗は避けられます。

### 失敗②：BGMが5秒で停止する罠

**症状**：BGMをHTMLに追加してプレビューしたら、最初の5秒だけ音が鳴り、その後完全に無音になる。

**原因**：`<audio>` タグに `class="clip"` を付けていたためです。Hyperframesでは `class="clip"` が付いた要素は**シーン切替時に自動で非表示**になります。シーン1（0〜8秒）が終わると同時に、BGMの `<audio>` 要素も「非表示」扱いになって停止していました。

**解決**：BGMは「シーン制御の対象外で、動画全体を通して継続再生する独立トラック」なので、`class="clip"` を付けてはいけません。

```html
<!-- ❌ 間違い：シーン切替で停止する -->
<audio id="bgm" class="clip" src="..." />

<!-- ✅ 正解：動画全体で継続再生 -->
<audio id="bgm" src="..." />
```

### 失敗③：MP4で完全無音になる事件

**症状**：プレビューでは部分的に音が鳴っていたBGMが、`npm run render` で出力したMP4では完全に無音になっていた。

**原因**：複合的な問題が絡んでいました。

- `data-volume="0"` を初期値にして、GSAP（アニメーションライブラリ）でフェードインさせる実装にしていた
- しかし**GSAPは音量(volume)プロパティをアニメートできない仕様**だった（視覚プロパティのみ対応）
- レンダラーは `data-volume="0"` を直接読んで、最後まで音量0のまま出力していた

**解決**：`data-volume="0.35"` のように**固定値で直接指定**する。フェードイン・アウトはFFmpegで音声ファイルそのものに事前加工しておく。

```bash
# Oboroにフェードを焼き込んだファイルを生成
ffmpeg -i Oboro.mp3 -af "afade=t=in:st=0:d=2,afade=t=out:st=87:d=3" -t 90 Oboro_faded.mp3
```

> 【独自検証】4回失敗してたどり着いた正解です。最初は「GSAPで音量変えればいい」と思っていましたが、**Hyperframes公式ドキュメント**を読み直して `data-volume` がレンダラー直読みの静的値だと判明しました。「失敗してから公式仕様を読み直す」のは私の悪い癖です。最初から仕様書に当たれば1時間で済んだはずです。

## BGMはどう追加するのが正解ですか？

**`data-volume` に直接値を書くだけが正解です。GSAPで volume をアニメートするのは禁止、フェードはFFmpegで音声ファイルに事前加工するのが確実です。公式ドキュメントから判明した正しい手順を共有します。**

BGM追加の正しいプロセスは以下の通りです。

### Step 1: BGMファイルを入手

無料のBGM配布サイトを使います。私が選んだのは**PeriTune**の「Oboro」（尺八×琴の和風BGM）でした。商用利用OK、クレジット表記任意で、八王子竹紙研究会の世界観にぴったりでした。

| サイト | 特徴 | 商用利用 |
|---|---|---|
| PeriTune | 和風BGM豊富、ループ素材付き | ◎ |
| DOVA-SYNDROME | 日本語サイト・登録不要・量豊富 | ◎ |
| YouTube Audio Library | Googleアカウント不要 | ◎ |

### Step 2: フェード加工した音声を準備

FFmpegでフェードイン・アウトを音声ファイルに焼き込みます。

```bash
ffmpeg -i assets/audio/Oboro.mp3 \
  -af "afade=t=in:st=0:d=2,afade=t=out:st=87:d=3" \
  -t 90 \
  assets/audio/bgm-oboro-faded.mp3
```

これで「2秒かけてフェードイン、87秒〜90秒で3秒かけてフェードアウト、全体90秒」のファイルが生成されます。

### Step 3: HTMLに `<audio>` タグを追加

```html
<audio
  id="bgm-oboro"
  data-start="0"
  data-duration="90"
  data-track-index="10"
  data-volume="0.35"
  src="assets/audio/bgm-oboro-faded.mp3"
></audio>
```

ポイントは4つ。

- `class="clip"` は付けない（シーン切替で停止するため）
- `data-volume` は固定値（0.35〜0.45が標準）
- `loop` 属性は付けない（キャプチャエンジンと相性が悪い場合あり）
- `data-track-index` は他のビジュアル要素と被らない番号（10など）にする

### Step 4: ffprobeで音声トラックを確認

レンダリング後、本当に音声がMP4に含まれているか技術的に確認できます。

```bash
ffprobe -v error -show_entries stream=codec_type renders/最新のファイル.mp4
```

`codec_type=audio` が表示されれば成功です。

> 【独自検証】私はこのプロセスにたどり着くまでに4回失敗しています。①class="clip" 削除だけで直ると思った、②GSAPで音量制御できると思った、③`loop` 属性で長さを補えると思った、④フェードはHTML側で制御できると思った。すべて公式ドキュメントを読み直して初めて正解が判明しました。**「先にドキュメントを読む」を徹底すれば1時間で完成していたはずです**。

## よくある質問（FAQ）

**Q. WindowsでもMacと同じようにできますか？**
A. はい、できます。Node.jsとFFmpegさえ入ればWindowsでも動作します。ただし、私が今回試したのはMac環境(Apple Silicon)なので、Windowsでの最適化は検証していません。Apple Siliconはvideotoolboxで高速エンコードできるメリットがあります。

**Q. Claude Codeの利用料金はかかりますか？**
A. Claude Codeはターミナルツール自体は無料ですが、利用にはAnthropicのClaude Pro以上のプランが推奨です（月額20米ドル前後）。今回の動画制作1本分の利用量は、Claude Pro契約の通常範囲内に収まりました。

**Q. PeriTuneのBGMは商用利用OKですか？クレジット表記は必要ですか？**
A. PeriTuneのライセンスでは商用利用OK・加工改変OK・クレジット表記任意です。ただし楽曲単体の転売や「楽曲紹介」目的の動画への利用は禁止されています。詳細は公式サイトのライセンスページをご確認ください。

**Q. 動画制作にかかる本当のコスト（電気代・時間も含めて）は？**
A. ソフトウェア費用はゼロ円。所要時間は私の場合、設計2時間・素材選定1時間・生成と修正3時間・レンダリング数十分で、合計**約7時間**でした。2本目以降はこの半分以下に短縮できる見込みです。

**Q. 失敗しても元に戻せますか？**
A. はい、Hyperframesは `renders/` フォルダにレンダリングごとのMP4を**タイムスタンプ付きで自動保管**してくれます。修正前のバージョンが残るので、「やっぱり前の方が良かった」と思った時にいつでも戻れます。
