## はじめに——「対話するAI」から「働くAI」へ

あなたは今、Claude Codeをどう使っていますか？

コードを書くとき、アイデアを整理するとき、調べ物をするとき——多くの人は「質問して、答えをもらう」という使い方をしています。これはこれで強力です。しかし、その使い方には一つの大きな前提があります。

**「自分が画面の前にいるとき」しか動かない**、という前提です。

2026年4月、Anthropicはその前提をひっくり返す機能をリリースしました。その名も「Routines（ルーチン）」。

一言でいえば、「あなたがPCを閉じて寝ている間も、AIが自律的に仕事を続ける」仕組みです。

想像してみてください。毎週月曜の朝、出社してPCを開いたら、先週の売上データをまとめた報告スライドのドラフトが届いている。金曜の夜に送った企画メールの内容が、すでにCRMに登録されている。チームのバックログが、気づいたら整理されてSlackに要約が来ている。

これはSFではありません。Routinesを使えば、今日から設定できることです。

本記事では、「Claude Codeはコードを書くためのツール」という固定観念を壊しながら、Routinesが非エンジニアを含むあらゆる業務にどんな変化をもたらすのかを、具体的なユースケースと一緒に解説します。エンジニアがチームメンバーに「こういうことができるんだよ」と見せるための記事として使っていただけると嬉しいです。

## 第1章：Routinesとは何か——3つのトリガーと「クラウドで動く」という革命

### そもそも「ルーチン」とは

Routinesとは、**プロンプト（AIへの指示）・操作対象のリポジトリ・外部ツールとの接続設定を一つにまとめ、Anthropicのクラウド上で自動実行する仕組み**です。

従来のClaude Codeは「あなたが話しかけたときだけ動く」ものでした。Routinesはその制約を取り払い、Claude Codeを「定期的に、あるいは特定のイベントをきっかけに、自律的に動くエージェント」に変えます。

最大の特徴は、**あなたのPCがスリープ状態でも、電源が切れていても動き続ける**点です。処理はAnthropicのクラウドインフラ上で実行されるため、あなたのマシンの状態に依存しません。

### 3つのトリガー

Routinesは、以下の3種類のトリガー（起動条件）を持ちます。一つのルーチンに複数のトリガーを組み合わせることも可能です。

#### ① スケジュールトリガー

「毎日夜9時に実行する」「毎週月曜朝8時に実行する」「平日の毎朝実行する」といった**時間ベースの定期実行**です。

最小間隔は1時間。それより短い間隔（例：5分ごと）は設定できません。しかし、「毎朝データをまとめて届ける」「週次で報告書を作る」といった用途には十分すぎるほどです。

例：
- 毎週月曜8時：先週のKPIをまとめてSlackに投稿
- 毎日23時：その日受信したリードメールをCRMに登録
- 毎週金曜15時：週次報告スライドのドラフトを生成

#### ② APIトリガー

**外部ツールやシステムからHTTPリクエストを受け取ったときに起動**する仕組みです。ルーチンごとに専用のエンドポイント（URL）とトークンが発行され、そこにPOSTリクエストを送るとルーチンが実行されます。

「監視ツールがアラートを検知したとき」「フォームが送信されたとき」「別のワークフローが完了したとき」など、イベント駆動型の自動化に使われます。

エンジニアが「こういうときに動かして」と設定しておけば、非エンジニアのチームメンバーが日常業務で自然に恩恵を受けられます。

#### ③ GitHubトリガー

**GitHubリポジトリ上のイベント（PRの作成・更新、リリースの公開など）に反応して起動**します。開発チームの動きに連動して自動で処理を走らせたいケースに使います。

例えば「新しいリリースが公開されたら、変更内容をまとめた社内向け報告を自動作成する」といったことが可能です。

### 「クラウドで動く」ことの意味

Routinesが従来の自動化スクリプトと決定的に異なるのは、単に「自動で実行される」だけでなく、**AIが状況を読み取り、計画を立て、外部ツールを操作し、結果をまとめる**という一連のプロセスを自律的にこなす点です。

スクリプトは「決められたことを決められた通りに実行する」ものです。Routinesは「目標を与えれば、どうやって達成するかをAIが判断して動く」ものです。

例えば「先週マージされたPRをスキャンして、ドキュメントと乖離している箇所を探し、更新用のPRを作成する」という指示を出せば、AIは自分でコードを読み、ドキュメントを確認し、差分を見つけ、PRを起票するという複数のステップを、人間が画面を見ていなくても実行します。

### Routinesと他の自動化手段の違い

Claude Codeには、Routines以外にも自動化の手段があります。混乱しないよう整理しておきましょう。

| 手段 | 実行場所 | PCが閉じていても動く？ | 主な用途 |
|------|---------|---------------------|---------|
| **Routines** | Anthropicのクラウド | ✅ 動く | 定期・イベント駆動の自律作業 |
| **Desktopスケジュールタスク** | あなたのPC | ❌ 動かない | ローカルファイルを使う定期作業 |
| **/loop** | 現在のセッション | ❌ セッション終了で停止 | セッション内の短期ポーリング |
| **GitHub Actions** | GitHubのCI/CD | ✅ 動く | コードのビルド・テスト・デプロイ |

PCを閉じても動き続けてほしい、かつローカルファイルに依存しない作業であれば、Routinesが最適な選択肢です。

## 第2章：ユースケース① 営業・CRM業務の自動化

### 「入力作業」がなくなる世界

営業職の人に聞くと、必ずといっていいほど出てくる不満があります。「CRMへの入力が面倒」「商談後の議事録をまとめる時間がない」「週次レポートを作るだけで半日かかる」——。

これらは、高い営業スキルを持つ人が、本来価値を発揮すべき「顧客との対話」ではなく、「データの転記・整理」に時間を使っている状態です。Routinesは、この構造を根本から変えます。

### シナリオ1：メール→CRM自動登録パイプライン

**使用するコネクタ（MCP）：Gmail + HubSpot**

毎日届く問い合わせメールや商談メール。これを手作業でCRMに入力している場合、Routinesで次のような自動化が実現できます。

**ルーチンの動き（毎日23時に実行）：**
1. Gmailを開き、当日受信した問い合わせ・商談関連メールを取得
2. 各メールから「会社名」「担当者名」「興味・関心のある製品」「予算感」「次のアクション」を抽出
3. HubSpotに該当する連絡先・商談レコードを作成または更新
4. 更新内容の要約をSlackの営業チャンネルに投稿

翌朝、営業担当は「昨日入力した案件」ではなく「昨日届いた案件の要約」を確認するところから一日を始められます。入力作業はゼロです。

### シナリオ2：週次CRM整理と「放置商談」アラート

**使用するコネクタ：HubSpot + Google Sheets**

「次のアクションが設定されていない商談」は、気づかないうちに失注につながるリスクがあります。毎週月曜の朝、このルーチンが動きます。

**ルーチンの動き（毎週月曜8時に実行）：**
1. HubSpotの全商談を読み込み、「次のアクション日が設定されていない」または「前回接触から2週間以上経過している」商談を抽出
2. 担当者・案件名・最終接触日・受注予定金額をGoogle Sheetsに書き出す
3. 「今週フォローすべき案件トップ5」を判定してSlackに投稿

営業マネージャーは月曜の朝、そのSlack投稿を見るだけで今週の優先事項を把握できます。

### シナリオ3：商談後の議事録→次アクション自動化

**使用するコネクタ：Google Drive（議事録） + HubSpot + Calendar**

商談後にメモを残したテキストをGoogle Driveの指定フォルダに置くと、ルーチンが自動的に処理します。

**ルーチンの動き（Google Driveのフォルダ更新をトリガーに実行）：**
1. 新規追加されたメモファイルを読み込む
2. 商談の課題・ニーズ・次回アクションを構造化して抽出
3. HubSpotの該当商談に活動記録を追加
4. 次回フォローアップ日をGoogle Calendarに自動登録

「メモを書いたら、あとは自動で整理される」——これが実現すると、商談後の管理業務がほぼゼロになります。

### この章のポイント

営業業務における自動化の核心は、「人間にしかできない判断・コミュニケーションに集中させる」ことです。データの転記・整理・アラートといった定型作業をRoutinesに任せることで、営業担当者は本来の仕事に専念できます。

## 第3章：ユースケース② コンテンツ制作の自動化

### 「ゼロから作る」をなくす

コンテンツ制作の現場でよく聞く悩みは「制作の前段階に時間がかかりすぎる」というものです。記事を書く前の情報収集、動画を作る前の素材準備、SNS投稿のためのフォーマット変換——これらの前工程をRoutinesが担います。

### シナリオ1：記事ブリーフの自動生成

**使用するコネクタ：Notion**

コンテンツチームのワークフローがこう変わります。

**変更前：** ライターに「来週の記事テーマ：AIエージェントの活用事例」と連絡→ライターがリサーチして構成案を作る（2〜3時間）

**変更後（ルーチン設定後）：**

毎週金曜17時、Notionの「テーマ一覧」データベースに追加されたテーマを読み取り、以下を自動生成してNotionページとして保存：

- ターゲット読者像
- 想定される読者の課題
- 記事の切り口・角度
- 見出し構成案（H2〜H3）
- SEOキーワード候補
- 参考にすべき競合記事のURL候補

月曜の朝、ライターはNotionを開くだけで「書くべきことが整理されたブリーフ」を受け取れます。リサーチ・構成の工程が大幅に短縮されます。

### シナリオ2：UGC動画広告の自動生成パイプライン

**使用するコネクタ：Fal.ai（画像生成）+ Remotion（動画編集）+ Notion（進捗管理）**

これは少し上級のユースケースですが、実際に実現されている事例です。

以前は5つの異なるSaaSツールを人間がつなぎながら作業していた動画広告制作が、一つのルーチンで完結します。

**ルーチンの動き（クリエイティブブリーフをNotionに登録したらトリガー）：**
1. Notionからブリーフ（ターゲット・トーン・訴求ポイント）を読み込む
2. Fal.aiに指示を送り、必要な画像素材を生成
3. 生成された素材をRemotionに渡し、動画編集を実行
4. 完成した動画ファイルをGoogle Driveに保存
5. NotionのプロジェクトDBを「完了」に更新してSlackに通知

ブリーフを登録したら、あとはSlackの完了通知を待つだけ。ツール間の手作業による受け渡しが完全になくなります。

### シナリオ3：SNS投稿の自動スケジューリング

**使用するコネクタ：Notion（コンテンツカレンダー）+ SNS API**

Notionのコンテンツカレンダーに「承認済み」マークをつけると、ルーチンが自動で各プラットフォーム向けにフォーマットを変換し、投稿スケジュールを設定します。

**ルーチンの動き（毎日9時に実行）：**
1. Notionカレンダーで当日・翌日に承認済みのコンテンツを取得
2. X（Twitter）向け：140字以内に要約、ハッシュタグを付与
3. LinkedIn向け：ビジネス文体に変換、引用や統計を強調
4. Instagram向け：視覚的な説明文とキャプションを生成
5. 各プラットフォームのAPIに投稿予約を送信

SNS担当者は「コンテンツを承認する判断」だけに集中できます。フォーマット変換・投稿作業はゼロです。

### この章のポイント

コンテンツ制作における自動化の効果は、「量を増やす」だけでなく「クリエイターが判断・創造に集中できる環境を作る」ことにあります。前工程・後工程をRoutinesが担うことで、制作プロセス全体の質と速度が上がります。

## 第4章：ユースケース③ プロジェクト管理の自動化

### チーム全員の「認知負荷」を下げる

プロジェクト管理で消耗する時間の多くは、「状況の把握・共有・整理」に費やされています。「誰が何をやっているか」「何が止まっているか」「今週何を優先すべきか」——これらを人間がまとめる作業をRoutinesが引き受けます。

### シナリオ1：バックログの自動整理とSlack朝報

**使用するコネクタ：Linear（またはJira） + Slack**

毎朝チームが迷子にならないための「地図」を、Routinesが自動で作ります。

**ルーチンの動き（毎週月〜金、朝8時に実行）：**
1. Linearの全イシューを読み込む
2. 前日に新規追加されたイシューにラベルを付け、担当者を割り当て
3. 「今日対応すべき優先度High」のイシューを抽出
4. 「着手中だが3日以上更新なし」の停滞タスクをピックアップ
5. これらをまとめてSlackの#daily-standupチャンネルに投稿

チームは毎朝Slackを開けば、その日の優先事項が整理された状態で確認できます。スタンドアップミーティングの時間が大幅に短縮され、会話の質も上がります。

### シナリオ2：リサーチ→タスク自動登録

**使用するコネクタ：Web検索 + ClickUp（またはNotion）**

「競合調査をして、気になった点をタスクに落とし込んでおいて」——このような依頼をRoutinesに任せられます。

**ルーチンの動き（毎週水曜夜に実行）：**
1. 指定した競合企業の最新ブログ・プレスリリース・製品アップデートをWebで収集
2. 自社への影響度・対応の必要性を判断
3. 「対応が必要」と判断した内容を構造化してClickUpに新規タスクとして登録
4. タスクに優先度・担当チーム・参考URLを付与
5. 週次のチームSlackに「今週の競合動向まとめ」を投稿

マーケターやプロダクトマネージャーが毎週手動でやっていた情報収集とタスク化の工程が、自動化されます。

### シナリオ3：週次プロジェクト報告の自動まとめ

**使用するコネクタ：Linear + GitHub + Slack + Google Docs**

プロジェクトマネージャーが毎週金曜に作成する「週次ステータスレポート」を自動化します。

**ルーチンの動き（毎週金曜16時に実行）：**
1. Linearで今週完了・進行中・ブロックされたイシューを集計
2. GitHubで今週マージされたPR数・コミット数を取得
3. これらのデータをもとに週次レポートを生成（完了事項・進行中・リスク・来週の計画）
4. Google Docsに保存してステークホルダーに共有リンクをSlack投稿

PMは「データを集める作業」ではなく「レポートを読んでコメントする判断」だけに専念できます。

### この章のポイント

プロジェクト管理における自動化の本質は、「情報の流れを設計すること」です。どこから情報を集め、どう整理し、誰に届けるか——この設計をRoutinesに落とし込むことで、チーム全員の認知負荷が下がります。

## 第5章：ユースケース④ 非エンジニアのプレゼン資料作成を劇的に効率化する

### 「資料作成の前工程」に消える時間

多くのビジネスパーソンが経験していることがあります。毎週の定例会議で同じような資料を作り直している、月末の経営報告のためにExcelとグラフと文章を何時間もかけて整える、顧客向けの提案資料を作るたびに同じような情報収集から始める——。

プレゼン資料作成の時間の多くは、実は「資料を作る作業」ではなく、「資料を作るための情報収集・整理・構成考案」という前工程に費やされています。Routinesはこの前工程を丸ごと引き受けます。

### シナリオ1：週次報告スライドの自動ドラフト生成

**使用するコネクタ：Google Sheets（KPIデータ）+ Notion（プロジェクト進捗）+ Google Slides**

毎週月曜の朝、会議室に入る前に報告スライドのドラフトが完成している——これを実現するルーチンです。

**ルーチンの動き（毎週日曜23時に実行）：**
1. Google Sheetsから先週のKPIデータ（売上・PV数・リード数など）を取得
2. Notionのプロジェクト管理DBから各プロジェクトの進捗・ステータスを読み込む
3. 前週との比較・増減率・トレンドを計算
4. 以下のスライド構成でGoogle Slidesにドラフトを自動生成：
   - 表紙（週次報告 / 日付）
   - 今週のハイライト（3点）
   - KPIサマリー（数値とグラフ）
   - プロジェクト進捗一覧（ステータス別）
   - 課題・リスク（要対応事項の抽出）
   - 来週の予定
5. SlackにGoogle SlidesのURLを投稿（「週次報告ドラフトが完成しました。ご確認ください」）

月曜の朝、担当者はSlackのリンクを開き、数字を確認してコメントを追記するだけ。ゼロから作る作業が完全になくなります。データが整っていれば、追記・修正含めて30分以内に完成させられるようになります。

### シナリオ2：会議前日の「資料ドラフト自動配信」

**使用するコネクタ：Google Calendar + Notion + Google Docs**

重要な会議が翌日に控えているとき、前日の夜にルーチンが動き、当日朝には資料の骨子ができています。

**ルーチンの動き（毎日22時にスケジュール実行）：**
1. Google Calendarから翌日の会議予定を読み込む
2. 会議タイトル・参加者・説明文をもとに、会議の目的を判断
3. Notionの関連プロジェクト・議事録・資料を参照して文脈を把握
4. 会議の目的に合わせた資料構成を生成：
   - 意思決定会議 → 背景・選択肢・推奨案・次のアクション
   - 報告会議 → 進捗・課題・数値・来週の計画
   - ブレスト会議 → 現状整理・論点・問いかけ
5. Google Docsにドラフトとして保存し、会議参加者にリンクを共有

「今日の会議、何を話せばいいか」という迷いがなくなります。すでに骨子が整った状態でブラッシュアップするだけなので、準備時間が大幅に短縮されます。

### シナリオ3：顧客提案資料の情報収集自動化

**使用するコネクタ：Web検索 + HubSpot + Google Docs**

初回提案に向けて顧客企業を調べる作業——事業内容・競合状況・課題・最新ニュース——をRoutinesが代行します。

**ルーチンの動き（HubSpotで商談ステージが「提案準備中」に変更されたらAPIトリガーで実行）：**
1. HubSpotから顧客企業名・担当者・業界を取得
2. Webで以下の情報を収集：
   - 企業の事業概要・最新プレスリリース
   - 業界トレンド・主要課題
   - 競合他社の動向
   - SNSやニュースでの最近の言及
3. 収集した情報を「企業調査シート」としてGoogle Docsにまとめる
4. 「自社製品との接点・提案のフック」を3点抽出して末尾に追記
5. HubSpotの該当商談にDocsのリンクを添付

営業担当者が「提案準備中」にステージを動かした瞬間から、ルーチンが調査を開始します。翌朝には「整理された調査シート」が届いており、提案内容の検討に集中できます。

### 非エンジニアが恩恵を受けるための「橋渡し」

ここで重要なのは、**非エンジニアがRoutinesを直接設定しなくてもよい**という点です。

実際の運用イメージはこうです：
- エンジニアがルーチンを一度設定する（30分〜1時間）
- 非エンジニアは「Notionにテーマを追加する」「CalendarにKPIデータを入力する」などの日常業務をするだけ
- 自動的に資料のドラフトが届く

ルーチンの設定はエンジニアの仕事、ルーチンの恩恵を受けるのはチーム全員——この分担が、組織全体での自動化を現実的にします。

### この章のポイント

プレゼン資料作成の自動化は「資料を完全に自動で作る」ことではなく、「人間が判断・編集・磨きをかけるための土台を自動で用意する」ことです。前工程の自動化によって、資料の品質を上げながら作成時間を大幅に削減できます。

## 第6章：MCPとの組み合わせ——自動化の「糊」としての役割

### Routinesを強力にする「コネクタ」の存在

ここまで読んできて「でも、どうやってGmailやNotionやHubSpotと連携するの？」と思った方もいるでしょう。その答えが「MCP（Model Context Protocol）」です。

MCPとは、Claude Codeが外部ツールと安全に連携するための規格です。「コネクタ」とも呼ばれます。適切なMCPサーバーを設定すれば、Claude Codeは対応するツールのデータを読み書きできるようになります。

### 主要なMCPコネクタと用途

現在利用可能な主要なコネクタの一覧です：

#### ビジネスツール系
| コネクタ | できること |
|---------|-----------|
| **Gmail** | メールの読み取り・送信・分類 |
| **Google Sheets** | スプレッドシートの読み書き・計算 |
| **Google Drive** | ファイルの読み取り・保存・共有 |
| **Google Slides** | スライドの作成・編集 |
| **Notion** | DB・ページの読み書き・ステータス更新 |
| **Slack** | メッセージ送信・チャンネル投稿 |

#### 営業・マーケティング系
| コネクタ | できること |
|---------|-----------|
| **HubSpot** | CRM・商談・連絡先の読み書き |
| **Airtable** | データベースの読み書き |
| **Linear** | イシュー管理・ステータス更新 |
| **ClickUp** | タスク作成・更新・割り当て |

#### クリエイティブ系
| コネクタ | できること |
|---------|-----------|
| **Fal.ai** | AI画像生成 |
| **Remotion** | 動画自動編集 |
| **Blotato / SNS API** | SNS投稿スケジューリング |

### コネクタを組み合わせる「設計力」

Routinesの真価は、複数のコネクタを組み合わせることで発揮されます。

例えば：
- **Gmail → HubSpot → Slack**：リードメールをCRMに登録してSlackで通知
- **Google Sheets → Google Slides → Slack**：KPIデータをスライドにまとめてSlack共有
- **Web検索 → Notion → ClickUp**：リサーチ結果をまとめてタスク化

重要なのは、**「情報の流れ」を設計すること**です。どのツールからデータを取り、どう処理して、どこに届けるか——このフローを言語で記述したものがルーチンのプロンプトになります。

### コネクタの注意点

コネクタを追加するほど、AIが扱う情報量（トークン）が増え、処理が重くなる可能性があります。「使えるから全部追加する」ではなく、「このルーチンに必要なものだけを追加する」という設計が重要です。

経験則として、2〜4個の well-chosen なコネクタであれば実用上問題ありません。5個以上を組み合わせる場合は、処理の分割（複数のルーチンに分ける）を検討しましょう。

## 第7章：現状の制限と注意点——リサーチプレビューの今を正確に理解する

### Routinesは「リサーチプレビュー」段階

Routinesは2026年4月14日にリサーチプレビューとして公開されました。これは「一般提供前の試験運用」という位置づけであり、今後仕様・制限・料金体系が変更される可能性があります。

「できること」だけでなく「できないこと・注意すること」を正確に理解した上で使うことが、期待値ズレを防ぐために重要です。

### 制限1：利用可能なプランと1日の実行回数上限

Routinesは以下のプランで利用できます（Freeプランでは利用不可）：

| プラン | 1日あたりの最大実行回数 |
|-------|----------------------|
| **Pro** | 5回 |
| **Max** | 15回 |
| **Team / Enterprise** | 25回 |

実行回数はサブスクリプションの使用量プール（トークン）を消費します。上限を超えた場合、組織設定で「追加使用量（extra usage）」を有効にしていれば従量課金で実行継続が可能です。

**実務上の影響：** Proプランで1日5回というのは、使い方によっては制約になります。例えば「毎時間実行したい」という用途には対応できません。複数のルーチンを走らせる場合は、プランの選択と実行回数の設計に注意が必要です。

### 制限2：スケジュールの最小間隔は1時間

スケジュールトリガーは、最短でも「1時間に1回」が上限です。5分ごと・10分ごとの実行は現時点では対応していません。

高頻度のポーリングが必要な場合は、`/loop` コマンド（セッション内）やGitHub Actionsなど別の手段を検討してください。

### 制限3：ローカルファイル・ローカルアプリへはアクセス不可

Routinesはクラウド上の独立した環境で実行されます。そのため：
- あなたのPC上のローカルファイルにはアクセスできない
- PC固有の認証情報（ブラウザのCookieなど）は使えない
- ローカルにインストールされたアプリは操作できない

「ローカルのExcelファイルを読んで処理する」といったことは、Routinesでは対応できません。その場合は「Desktopスケジュールタスク」（PCが起動している必要がある）を使います。

逆にいえば、**クラウドツール（Google Workspace・Notion・HubSpot・Slack等）を主に使っている職場であれば、Routinesは十分に機能します。**

### 制限4：Routinesは個人アカウントに紐づく

ルーチンは作成者の個人claude.aiアカウントに属し、チームメイトと直接共有されません。ルーチンが実行するすべての操作（GitHubへのコミット、Slackへの投稿、外部ツールへの書き込みなど）は、**ルーチンを作成したユーザーの名義で実行されます。**

チームで使う場合の設計指針：
- エンジニアなど技術担当者がルーチンを設定・管理する
- 各ツールの権限（Slack・Notion・GitHubなど）は設定者のアカウントに付与する必要がある
- 「誰が作ったルーチンか」を明確にしてチームで管理する

### 制限5：GitHubトリガーにはレート制限がある

リサーチプレビュー中、GitHubのWebhookイベントはルーチンごと・アカウントごとに1時間あたりの上限があります。上限を超えたイベントは破棄されます。頻繁にPRが作成されるリポジトリでは、イベントがスキップされる可能性があります。

### 制限6：GitHubへのプッシュはデフォルトで `claude/` プレフィックスブランチのみ

安全のため、Routinesがコードをプッシュできるのはデフォルトで `claude/` で始まるブランチ名に限られます。`main` や `develop` などの保護ブランチへの直接プッシュは、設定で明示的に許可しない限りできません。

これは意図的な安全設計であり、ルーチンが誤って重要なブランチを書き換えることを防いでいます。

### 制限のまとめと付き合い方

| 制限 | 内容 | 回避策 |
|-----|------|-------|
| 実行回数上限 | Pro:5回/日、Max:15回/日 | プランを上げる or ルーチンを厳選する |
| 最小間隔1時間 | 高頻度実行は不可 | /loop や GitHub Actions で補完 |
| ローカルアクセス不可 | PCのファイル・アプリは扱えない | Desktopタスクと使い分ける |
| 個人アカウント紐づき | チーム共有は直接できない | 管理者を決めて一元設定 |
| GitHubレート制限 | 高頻度イベントは破棄 | 重要イベントだけに絞る |

重要なのは「制限があるから使えない」ではなく、「制限を理解した上でRoutinesに向いている仕事を見極める」ことです。

## 第8章：どこから始めるか——最初の一歩の踏み出し方

### まず試すべき「最初のルーチン」

Routinesを初めて使う場合、複雑なユースケースから始める必要はありません。「週次の情報まとめ」のような、シンプルで失敗しても問題ない用途から始めるのがおすすめです。

#### 初心者向けルーチン例：週次ニュースまとめSlack投稿

**前提：** Slackコネクタが設定済みであること

**プロンプト例：**
```
毎週月曜の朝8時に、以下の作業を行ってください：
1. 「生成AI」「Claude」「Anthropic」に関する先週のニュースをWebで検索する
2. 重要度の高いニュースを5件選ぶ
3. 各ニュースについて、タイトル・概要（2〜3行）・重要なポイントをまとめる
4. Slackの#ai-newsチャンネルに投稿する
フォーマット：各ニュースの見出しをH2にして、箇条書きで要点を記載する
```

これだけで、毎週月曜の朝にAIが収集・整理した情報がSlackに届きます。

### 設定の手順

Routinesは `claude.ai/code/routines` から作成できます。以下の手順で進めます：

**1. ルーチンの作成**
- 「New routine」をクリック
- ルーチン名を入力（例：「週次AIニュースまとめ」）
- プロンプトを入力（何をするか、どんな形式で出力するか）

**2. トリガーの設定**
- 「スケジュール」を選択
- 実行頻度を選ぶ（毎日・平日・週次など）
- 実行時刻を設定

**3. コネクタの追加**
- 使用するツール（Slack・Notionなど）のコネクタを追加
- 認証を通す（初回のみ）

**4. テスト実行**
- 「Run now」で即時実行してテスト
- 出力を確認して問題なければ保存

CLIからも設定可能で、`/schedule` コマンドを使えばチャット形式でルーチンを作成できます：

```
/schedule 毎週月曜8時にAIニュースをまとめてSlackに投稿
```

### 「プロンプトの書き方」が成否を分ける

Routinesで最も重要なのは、プロンプトの質です。ルーチンは自律的に動くため、**「曖昧な指示」は意図しない動作につながります。**

良いプロンプトの条件：
- **何をするか**が明確（「ニュースをまとめる」ではなく「5件を選んで各2〜3行で要約する」）
- **どこから情報を取るか**が明確（「Webで検索する」「NotionのDBを読む」）
- **どこに出力するか**が明確（「Slackの#チャンネル名に投稿する」）
- **成功の定義**が明確（「完了したらDoneと出力する」など）

最初は小さく始めて、動作を確認しながらプロンプトを改善していくのが最も確実な進め方です。

## おわりに——「夜中に働くAI」の時代に、私たちは何をするか

### Routinesが変えること

Claude Code Routinesは、AIとの関係を根本的に変えます。

今まで：AIは「質問に答えるツール」——あなたが問いかけるとき、画面の前にいるときだけ動く
これから：AIは「自律的に働くパートナー」——あなたが何をしていても、どこにいても、必要な仕事を進める

これは単なる「効率化」ではありません。「人間が担う仕事の性質の変化」です。

データの転記・整理・収集・通知といった「情報処理の定型作業」はRoutinesが担い、人間は「判断・創造・対話」に集中できます。これは、AIが登場した当初から言われていた「AIは仕事を奪うのではなく、仕事の質を変える」という変化が、ようやく日常業務レベルで実感できる形で現れてきた姿です。

### 非エンジニアへのメッセージ

この記事を読んで「でも、自分はエンジニアじゃないから設定できない」と思った方へ。

Routinesの設定自体は、エンジニアに一度お願いすれば、あとは自分で何もしなくても恩恵を受けられます。「毎週この資料を作るのに3時間かかっている」「毎日同じデータを転記している」——そういう業務があれば、エンジニアに伝えるだけで自動化の扉が開きます。

自動化の価値を一番わかっているのは、その仕事をしている当事者です。「こんなことを自動化できたら」というアイデアを、エンジニアに投げかけてみてください。

### エンジニアへのメッセージ

Routinesを使えるエンジニアには、「チームの仕事を変える設計者」という新しい役割が生まれています。

コードを書くだけでなく、「チームのどの業務をどう自動化するか」を設計し、実装する。その影響範囲は、エンジニア以外のチームメンバーにも広がります。

「週次報告資料のドラフトが月曜の朝に届いている」という体験をチームに届けられるのは、Routinesを動かせるあなただけです。

### まとめ：今日から試せること

1. **claude.ai/code/routines** にアクセスしてRoutinesの管理画面を確認する
2. 「毎週やっている繰り返し作業」を一つ書き出す
3. そのタスクをRoutinesで自動化できないか、この記事のユースケースと照らし合わせてみる
4. シンプルなルーチン（週次ニュースまとめなど）を一つ作ってみる

Routinesはまだリサーチプレビュー段階です。制限もあります。でも、今から使い始めることで、機能が正式リリースされたときに最大の恩恵を受けられるのは、今試している人たちです。

あなたの仕事、夜中にAIが片付けている——そんな朝が、もうすぐ当たり前になります。
